## Analysis Notes & Limitations

### Confidence Model

Chain analysis heuristics are **probabilistic**, not deterministic.
Each heuristic assigns a confidence level based on signal strength:

- **High confidence**: Multiple corroborating signals (e.g., script type match + round number agreement)
- **Medium confidence**: Single clear signal (e.g., script type match alone)
- **Low confidence**: Weak signal (e.g., value analysis in isolation)

### Known Limitations

| Heuristic | Known False Positives | Known False Negatives |
|-----------|----------------------|----------------------|
| CIOH | CoinJoin, batch payments, payroll txs | Always high recall |
| Change Detection | 1-output txs, identical output types | Cross-tx change not trackable |
| CoinJoin | Batch payments with equal outputs | JoinMarket-style CoinJoins |
| Consolidation | Payments with many inputs | Small consolidations (2-3 inputs) |
| Peeling Chain | Only detects within-block continuations | Cross-block peeling invisible |
| Address Reuse | N/A | Cross-block reuse not tracked |

### Privacy Implications

Chain analysis exploits the fact that Bitcoin transactions are **public** and **permanent**.
The heuristics in this report represent techniques used by blockchain analytics firms
to cluster addresses and identify transaction patterns. Users seeking privacy should
consider CoinJoin, Lightning Network, or other privacy-enhancing protocols.
